## 1. プロジェクト概要

### 目的

少人数（最大5人のグループ）で使う、筋トレとランの記録アプリを作る。
「シンプルだけど凝っていて、毎日開きたくなる」こと、そして**休養日を責めないこと**を大切にする。

柱は次の2つ。

- **ゴースト対戦**: 前回の自分の記録と並べて記録する。前回の値が最初から入っていて、「できた」を1タップで押せる
- **仲間と見せ合う**: 誰が記録したか（足跡）・スタンプ・コメント・今週のグループ合計で、仲間とゆるくつながる

あわせて、要件定義 → 設計 → 実装 → デプロイの流れで開発し、次のスキルを身につける。

- Next.js（静的書き出し）＋ NestJS（AWS Lambda）＋ PostgreSQL による構成
- Cookie セッション認証・グループへの招待・署名付き URL による動画の保存
- 地図・GPX ファイルの読み取り・ブラウザ内の動画撮影

### 背景

- プログラミングスクール RaiseTech の課題として開発する。課題の条件は「複数のユーザーが使うサービスで、データを双方向にやり取りすること」
- 本アプリでは、ユーザー同士のつながりを「グループへの招待参加」で表す（一方通行のフォローは作らない）。足跡・スタンプ・コメントで双方向のやり取りを行う
- 前作（X風 SNS）とは別の技術スタックで作る

### 差別化ポイント（意図的に作らないもの）

| 項目 | 方針 |
|------|------|
| 全体ランキング | **作らない**。比べるのは前回の自分と仲間だけ |
| 連続日数（ストリーク） | **表示しない**。途切れると0に戻る数字は、長く続けた人ほど休めなくする。代わりに「今週の7マス」を出す（休んだ日は淡い色のマスで、欠けに見せない） |
| 仲間の連続日数・順位 | **表示しない**。自分が休んでも仲間に損をさせない |
| 目標の未達表示 | **作らない**（目標設定の機能を持たない） |

## 2. 前提条件・制約事項

### 前提条件

- 開発環境は Windows 11 PC + VS Code（Claude Code 拡張）とする
- 利用者はスマートフォンのブラウザで使う（ネイティブアプリではない）
- 日付は日本時間で扱う。週は月曜に始まり日曜に終わる
- 技術スタックは [9. 技術スタック](#9-技術スタック) のとおり（決定済みのもののみ）

### 制約事項

- 提出の目標は 2026-11-15、期限は 2026-11-20
- 原則無料で運用する。課金が発生する操作（AWS の構築・有料 API）は、実行前に必ず確認する
- ホーム画面のウィジェットは作れない。プッシュ通知はホーム画面に追加した場合のみ使えるため「できれば」とする
- 外部サービスとの直接連携（Strava・Apple HealthKit・Google Health Connect 等）は行わない。ランの記録は GPX ファイルの取り込みで受け取る
- 動画の変換サーバーは置かない（ブラウザで撮った形式のまま保存する）
- 秘密情報（DB の接続文字列・認証の署名鍵等）は Git にコミットしない

## 3. 対象ユーザー（ペルソナ）

### ペルソナ 1：会社員・佐藤さん（34歳）

| 項目 | 内容 |
|------|------|
| 運動の習慣 | 仕事のあとに週2〜4回、筋トレかランをする。続いたり途切れたりしてきた |
| 利用目的 | 前回の自分より少しでも伸びたことを確かめたい。友達4人とゆるく続けたい |
| ITリテラシー | SNS やメッセージアプリは毎日使う |
| 利用環境 | スマートフォンのブラウザ |
| 困りごと | 連続記録のアプリは、一度休むと0に戻ってやる気がなくなる |

### ペルソナ 2：ランが中心の友人・田中さん（29歳）

| 項目 | 内容 |
|------|------|
| 運動の習慣 | 週末に長めのラン、平日に短いラン。ラン用のアプリで記録している |
| 利用目的 | ラン用のアプリから書き出した GPX ファイルを取り込み、仲間に走ったルートを見せたい |
| ITリテラシー | 高い。ファイルの書き出しもできる |
| 利用環境 | スマートフォンのブラウザ |
| 困りごと | ラン用のアプリはランしか記録できず、筋トレの仲間と同じ場所で見せ合えない |

### ユーザーが抱える課題と解決

- 連続記録のアプリは、休むと数字が0に戻り、休養日をとりにくい
  → 連続日数を持たず「今週の7マス」で見せる。休んだ日は淡い色のマスになり、月曜にまっさらから始まる
- 記録の入力が面倒で続かない
  → 前回の値が最初から入っていて、「できた」を1タップで押せる。記録の直後に短い祝福が出る
- 1人だと続かないが、大人数の SNS は疲れる
  → 最大5人のグループで、足跡・スタンプ・コメントだけの静かなつながりにする

## 4. 機能要件

主要機能の概要を以下に示す。**受け入れ条件・ユースケースを含む詳細は [機能一覧（features.md）](./features.md)（基本設計で作成）を参照。**
工数はすべて見積もり（推測）であり、実装の最初の数件で実測して補正する。

### 4.1 必須

| No | 機能名 | 概要 | 遅れたときに削る順 |
|----|--------|------|------|
| F-01 | ユーザー登録・ログイン | メールアドレス + パスワード。Cookie セッション | — |
| F-02 | グループ | グループの作成・招待リンクでの参加・退出。最大5人 | — |
| F-03 | 筋トレの記録 | 種目・重量・回数。前回の値が最初から入り、「できた」を1タップで記録できる | — |
| F-04 | ランの記録（手入力） | 距離・時間を入力して記録する | — |
| F-05 | ゴースト（前回の自分） | 記録中に前回の自分と並ぶバーを出し、勝ち負けを見せる | — |
| F-06 | 記録直後の祝福 | 0.8秒の短い祝福（タップで飛ばせる）。自己ベストには「ベスト」の札 | — |
| F-07 | 継続の表示 | ホームに「今週の7マス」（記録した日は色、記録のない日は淡い色。連続日数は持たない）。2日以上空いた後の最初の記録は「おかえり」で祝う。前日の記録や空き日数に応じて、責めない一言を出し分ける | — |
| F-08 | 今日は休む | ホームから1タップで休みを記録する。仲間の足跡に「おやすみ」と出て、仲間は休み用のスタンプを返せる | ①（最初に削る） |
| F-09 | 仲間の足跡・週の合計 | 仲間タブに、記録した人（足跡）と今週のグループ合計を出す | — |
| F-10 | スタンプ・コメント | 記録にスタンプを付ける（同じスタンプの二重付与は防ぐ）。コメントは定型文＋自由入力（50字まで）。自分のコメントは削除できる | — |
| F-11 | 初回の体験 | 説明なしで60秒以内に最初の1セットを記録できる。お試しのゴーストと並べる | ②（お試しゴーストを削る） |
| F-12 | 筋肉ヒートマップ | 自分タブで、今週鍛えた部位を体の図に色で示す | ⑤（部位の一覧表示にする） |
| F-13 | 2秒ラストレップ動画 | 画面の中で2秒だけ撮影し、保存する。仲間に見えるのはその週の終わりまで、本人はずっと見られる | ③（写真にする） |
| F-14 | GPX の取り込み | ラン用アプリから書き出した GPX ファイルを読み、距離・時間・ルートを記録する | — |
| F-15 | ランの地図 | 記録したランのルートを地図に表示する | ④（距離・ペースの数字だけにする） |
| F-30 | オフライン記録 | 電波がなくても筋トレ・ランの記録（手入力）を端末に先に保存し、つながったら自動で送る。「できた」を押した瞬間に画面へ反映する。範囲は記録の保存だけで、表示は最後に読んだ内容を出す | — |

### 4.2 できれば（必須がそろってから、上から順に）

記録の積み重ねを見る画面（F-22・F-26・F-27・F-28・F-29）は、自分タブから1つ深い「記録をくわしく」画面にまとめる（設定・ユーザー情報と同じ階層）。

| No | 機能名 | 概要 |
|----|--------|------|
| F-22 | 週・月・年の切替 | 今週の7マス → 月のカレンダー → 1年分のマスを切り替えて見る。休んだ日の色は全期間で同じにし、欠けに見せない |
| F-26 | 今月の数字 | 今月動いた日・休んだ日を足し算で出す（連続ではないので減らない）。総重量を身近な物に換算する（例: 「今月は軽自動車3台ぶん」） |
| F-27 | グラフ | 週ごとの総重量・ランの週間距離を棒グラフで出す。目標線は引かない |
| F-16 | 友達とのゴースト | 仲間の記録とも並べて記録する |
| F-17 | 地図ゴースト | 前回のルートと並走する |
| F-18 | FIT の取り込み | FIT ファイルも読めるようにする |
| F-19 | 今日の部位が光る | 記録直後の祝福の中で、F-12 と同じ部品を使って今日使った部位を光らせる |
| F-20 | 今月の記録日数 | 祝福に「今月◯日目」を重ねる |
| F-21 | あとから記録 | 昨日の分をあとから入れる。「遅れて記録」の小さな札が付く |
| F-23 | メニュー提案 | 前回の記録からルールで次のメニューを提案する。説明文は無料枠の AI で言い換える（数値は変えない。失敗時はテンプレートのまま） |
| F-24 | 友達のメニューのコピー | 仲間のメニューを自分の記録に取り込む |
| F-25 | ホーム画面への追加・通知 | PWA としてホーム画面に追加でき、通知を受け取れる |
| F-28 | 走った距離で日本縦断 | ランの累計距離で、日本地図の上の決まった道を進む。「あと◯km」は出さず、今いる場所だけを見せる |
| F-29 | スタンプ帳 | 「初めての5km」「累計10回」など、初めて・累計だけで増えるバッジ（連続・週◯回の型は作らない） |

### 4.3 やらない

全体ランキング／連続日数の表示／一方通行のフォロー・投稿ごとの公開範囲／目標設定／グループで倒すボス戦／外部サービスとの直接連携／動画の変換サーバー／マスコット

## 5. 非機能要件

### 5.1 対応ブラウザ

| 端末 | ブラウザ |
|------|---------|
| Android | Google Chrome 最新版 |
| iPhone | Safari 最新版 |
| PC（開発・確認用） | Google Chrome / Microsoft Edge 最新版 |

### 5.2 性能

| 項目 | 目標 |
|------|------|
| 画面初期表示 | 3秒以内 |
| 記録の保存（「できた」を押してから） | 1秒以内 |
| 一覧の表示 | 段階的に読み込む（一度に全件取得しない） |

### 5.3 レスポンシブ対応

- スマートフォン（幅 360px 以上）を主対象とする。PC では中央に寄せて表示する

### 5.4 セキュリティ

| 項目 | 対策 |
|------|------|
| パスワード保管 | 認証ライブラリ（better-auth）のハッシュ化に任せ、平文では保存しない |
| 認証 | Cookie セッション。API を画面と同じサイト（CloudFront の `/api/*`）に置く |
| SQL インジェクション | ORM（Drizzle）のパラメータ渡しを使い、SQL 文字列を手で組み立てない |
| XSS | React の自動エスケープを使う。`dangerouslySetInnerHTML` は使わない |
| 他グループのデータ | API で「同じグループのメンバーか」を毎回確かめる |
| 招待リンク | 推測できない値にし、有効期限と人数上限（5人）を確かめる |
| 動画 | 署名付き URL で S3 に直接置く。見られる期間は URL の発行で制御する |
| アップロード | GPX・動画のサイズに上限を設け、形式を確かめる |

### 5.5 データ・通信

| 項目 | 内容 |
|------|------|
| データ永続化 | PostgreSQL（Neon Free）。マイグレーションは Drizzle で管理 |
| ファイル保存 | 動画・GPX は AWS S3 |
| 通信 | REST API（JSON）。本番は HTTPS |
| 日付 | 記録には日本時間の日付を持つ（深夜0時前後の記録が前後の日にずれないようにする） |
| オフライン | 送れなかった記録は端末に残し、つながったら送り直す。同じ記録が二重に保存されないよう、記録ごとに端末で作った ID を持つ。使う技術は基本設計で比較して決める |
| ホスティング | S3 + CloudFront（画面）／Lambda（API）。詳細は infrastructure.md（基本設計で作成） |

## 10. リスクと対策

| # | リスク | 影響 | 対策 |
|---|--------|------|------|
| 1 | 工数の超過（必須の見積もり約19〜30日に対し、使えるのは約14〜20日） | 期限に間に合わない | 必須を最小版にしてある。実装の最初の数件で速さを実測し、遅れたら [4.1](#41-必須) の削る順で落とす |
| 2 | iPhone の Safari で動画の撮影形式が想定と違う | 動画が保存・再生できない | 技術検証で PC は確認済み。スマートフォン実機での確認を残している。だめなら写真に切り替える（削る順③） |
| 3 | 日付の境目のずれ（日本時間と UTC） | 7マス・おかえりの判定が1日ずれる | 日本時間の日付を記録に持つ。日曜 23:59／月曜 0:00 の境目をテストする |
| 4 | 他グループの記録・動画が見えてしまう | 情報漏えい | API でメンバーかを毎回確かめる。動画は署名付き URL で期間を区切る |
| 5 | 壊れた GPX・巨大なファイル | 取り込みの失敗・処理の停止 | サイズ上限・壊れた XML・線0本を自前で検査し、エラーを返す |
| 6 | 機能の作りすぎ | 必須がそろわない | 必須がそろうまで「できれば」に着手しない |
| 7 | ドキュメントと実装のずれ | 混乱・手戻り | 実装を「正」としてドキュメントを修正する。同じ内容を複数ファイルに書かない |
