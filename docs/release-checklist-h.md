## S1: Lambda メモリ 512 → 1024

**なぜ**: Lambda の CPU はメモリに比例する。512MB だと眠っていた後の最初の1回（コールドスタート）が5秒前後かかった。1024MB なら CPU が2倍になり、起動が短くなる見込み（効果は apply 後に測る。**推測**）。
**差分**: `infra/variables.tf` の `lambda_memory_mb` の既定を 512 → 1024（これで `lambda.tf` の `memory_size` が変わる）。

```
cd infra
terraform plan        # 変更が「Lambda のメモリ 512→1024（in-place）」だけであることを見る
```

- 見るところ: `aws_lambda_function` の `memory_size` だけが変わる。ほかのリソースの作り直し（`must be replaced`）が出たら**止めて Claude に見せる**
- 課金: 実行時間 × メモリで決まる。1024 は 512 の2倍の単価だが、速く終わるぶん差は小さい。AWS の請求画面（Billing）で現在の利用を見てから進める
- ⚠ `terraform apply` は本人が行う。直した後に、眠った状態の1回目の表示時間を測り、docs/features.md 2.30 の「S3・S4 の体感」に書き足す

## U17: 日本語ラベルの地図

**やること（Claude が済ませた）**: `scripts/make-ja-map-style.py` が OpenFreeMap の positron から `frontend/public/map/style-ja.json` を作る。地名ラベル 19 個を「`name:ja` → `name`」の順に読む式に置き換えただけ。

**確かめたこと**（2026-11-18）: ①東京付近のタイル（z10）に `name:ja` が 17 か所入っている ②日本語の文字データ（かな・漢字の範囲）が OpenFreeMap から配られている（HTTP 200）。
**確かめていないこと**: 実際の地図画面で日本語が描かれる見た目（本人が公開版・ローカルで確認。手順は下）。

**有効にする**: 画面は `NEXT_PUBLIC_MAP_STYLE_URL` で切り替わる（ビルド時に埋め込まれる）。style-ja.json は画面と同じサイト（`/map/style-ja.json`）から配られるので、S3 の追加設定・CORS は要らない。

```
cd frontend
NEXT_PUBLIC_MAP_STYLE_URL=/map/style-ja.json npm run build
```

- `scripts/deploy.sh` は、この環境変数を付けていない（付けないと従来の英字ラベルのまま）。有効にするには deploy.sh の `npm run build` の行に上の変数を足す。**公開の挙動が変わるので、足すかどうかは本人が決める**
- 先にローカルで見る: `NEXT_PUBLIC_MAP_STYLE_URL=/map/style-ja.json npm run dev` → 走る画面の地図（東京や郡山）で、道路・地名が日本語か見る
- 戻し方: 環境変数を外して再デプロイ（既定の OpenFreeMap の positron に戻る）
- OpenFreeMap が止まったときの備えにはならない（タイル・文字データは外部のまま）。公開の後に PMTiles を自前配信する課題は別（docs/tech-stack.md の地図）
