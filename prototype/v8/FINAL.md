# プロトタイプ v8 ── v7 のキャラを LPC（64×64）に差し替え・全10ポーズ・編集画面

v7（M3「次の1枚」＋M1 の帯と道＋M2 の丸）の画面構成はそのままに、ドット絵のキャラを**自作の 32×32 から、無料素材 LPC の 64×64 に差し替えた**試作。要件 F-31（キャラ10ポーズ）・F-32（キャラの編集画面）の見た目と作り方の確認用。使い捨てのコードで、本番では作り直す。

## 見るもの

ローカルで確認するときは、`prototype/` で `python -I -m http.server 8123 --bind 127.0.0.1` を起動して開く（`file://` では画像が読めない）。

| ページ | 中身 |
|---|---|
| `v8/index.html` | アプリ本体（v7 と同じ画面）。ハッシュ `#today`・`#record`・`#rest`・`#friends`・`#me`。ホームの「時間帯」切替（朝・昼・後・休）でキャラのポーズが変わる |
| `v8/poses.html` | 10ポーズを、実寸で動かし、各コマ・縮小版と並べた一覧。「いつ出るか」付き |
| `v8/editor.html` | キャラの編集画面。男女・髪型・髪色・服の色・ズボンの色を選ぶ（保存はブラウザの localStorage のみ） |

## 10ポーズ

| ポーズ | いつ出るか | 元のコマ（LPC） | 描き足したもの |
|---|---|---|---|
| 待機 | 仲間・自分タブ、読み込み中 | idle 2コマ | ― |
| 準備OK | 昼以降でまだ記録していない（ホームの通常） | idle 2コマ | 片手のダンベル |
| トレーニング中 | 記録画面のヘッダー | idle ⇄ jump（ジャンプ準備） | 両手のダンベル（立つ⇄しゃがむ＝スクワット） |
| ガッツポーズ | 「できた」の結果・記録後のホーム | emote（腕を広げる）⇄ jump（拳を上げる） | 金の星2つ（交互に光る） |
| 朝の伸び | 朝（〜10時）でまだ記録していない | emote 3コマ | ― |
| くつろぎ | 休みの日 | sit（体育座り） | クッション・マグ・湯気・半目とまばたき |
| おかえり | 3日以上あいて開いたとき | jump（片手を上げる）⇄ idle | 朝の太陽 |
| 仲間への反応 | 仲間の足跡・スタンプ・コメント | emote 2コマ | ハート |
| ラン | ランの記録の結果 | run 8コマ | ― |
| 自己ベスト | 自己ベスト更新 | emote（腕を広げる） | 後光（回る）・胸の金メダル・星 |

合計 10ポーズ・28コマ。`prefers-reduced-motion` のときは1コマ目で止める。責める表情（泣く・弱る）は作っていない。

## 素材とライセンス

- 素材: Universal LPC Spritesheet Character Generator（Liberated Pixel Cup）の部品。男女の体・頭・髪5種・Tシャツ・ショーツ・靴 × 動き7種（idle・emote・sit・jump・run・climb・walk）＝105ファイル（`assets/lpc/`）
- **ライセンス**: 各ファイルに複数のライセンスが並ぶので、その中から**帰属表示だけが条件のもの（OGA-BY・CC-BY・CC0）を選んで使う**。CC-BY-SA・GPL は選ばない（派生物に同じ条件が及ぶため）。部品ごとの作者と選んだライセンスは `assets/lpc/CREDITS.md`
- 加工: ティール・紺・白・茶への**染め（輝度を保つ置換）**と、1マスずつ点で描き足した小物。加工した画像（`assets/lpc-frames/`）も同じ帰属表示の対象
- **本番での注意（要判断）**: OGA-BY は「作者の表示」が条件。リポジトリに `CREDITS.md` があるだけでなく、**配布するアプリの中にも作者表示（「このアプリについて」等）が要る**。要件への反映は別途

## 作り方（再現できる）

- `v8/tools/build_frames.py` が、`assets/lpc/` から `assets/lpc-frames/` の28枚を作り直す（Python 3 と Pillow）。実行して、現在の28枚と**全バイトで一致**することを確認済み（比較は R・G・B・A の全バイトで行う。Pillow の `getbbox()` は RGBA 画像では透明度しか見ないため、色だけの違いを見落とす。1ピクセルの色変更を検出できる陽性対照で確認した）
- `v8/index.html` は、v7 の `spriteSvg()` だけを差し替え。フレーム切替（`data-seq`・`data-ms`）は v7 のまま。コマは透明背景の PNG を SVG の `<image>` で重ね、`image-rendering: pixelated` で拡大

## 編集画面（F-32）のしくみ

- 部品の元絵（グレー）を `<canvas>` に重ねる順: 体 → 頭 → 靴 → ズボン → Tシャツ → 髪
- 色は実行時に置換: 各ピクセルの輝度 `0.299R + 0.587G + 0.114B` を保ち、選んだ色に掛ける。染めた結果は部品×色ごとにキャッシュ
- 選べるもの: 体2種（男・女）／髪5種／髪色6／服色8／ズボン色4／見せるポーズ3。PNG の枚数は部品×動きで決まり、**色を増やしても増えない**
- 肌の色は変えない（元絵が着色済みで、輝度での染めだと目の青まで染まる）

## 既知の弱点

- 輪郭が薄く、v7 の「太い紺の輪郭・ベタ塗り」とは絵柄が違う（画面に載せると、思ったほど浮かない）
- 「仲間への反応」の体は待機とほぼ同じで、ハートで違いを出している
- ガッツポーズの2コマ目は体が傾いて足が浮く（ジャンプのコマを流用）
- ランは正面向きの走り。拳が白っぽい（LPC の肌のハイライト色）
- 女性は髪型が男女共通で、違いは体型だけ
- スマホ実機での確認は未実施（スマホでローカルの `127.0.0.1` は開けないため、PR のプレビュー URL が要る）

## 本番に向けて（01-5 基本設計で決めること）

- 28枚の PNG は、スプライトシート1枚にまとめられる（読み込み回数を減らす）
- 色の置換は、サーバーで画像を作らず、画面の中（canvas）で行う案が軽い。選んだ組み合わせ（体・髪型・色）は、画像ではなく**設定値**としてデータベースに持つ
- 工数の目安（試作の実績）: 10ポーズ・編集画面・確認ページの試作は、1つの会話（セッション）の中で組めた。本番の画面ごとの組み込み・結果シート・仲間タブへの表示は、これに含まない
